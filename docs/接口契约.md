# 接口契约 v1

> **运行时的事实来源是 `engine/models.py`**（标准库 `dataclass`）。
> 本文件与 `schemas/itinerary.schema.json` 是给人看的文档，不参与运行时校验。
> 三者必须同步：改了 `models.py` 就要改这里和 `schemas/`。

---

## 零、三条纪律

1. **业务语义不许进 `models.py`。** "什么算太贵""什么算爬山""什么算近" 这类判断一律放 `config/scenarios/*.toml` 或 `data/`。代码里出现具体金额、具体时间、具体标签字面量 = 违规。
2. **冻结后只增不改。** 契约定稿后，只允许**加带默认值的新字段**；不许改字段名、改语义、删字段。
3. **改字段走版本。** 确需破坏性变更时 v1 → v2，并同步本文件 + `schemas/itinerary.schema.json` + `mock/*.json`，且在项目消息里通知对方。

---

## 一、PlanRequest（引擎唯一输入）

所有字段都有默认值 —— **空请求也必须能跑通**，这是"非法输入不崩"的前提。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `city` | str | `""` | 城市名，骨架阶段不参与计算 |
| `days` | int | `1` | 天数 |
| `start_time` | str | `"09:00"` | `"HH:MM"` |
| `end_time` | str | `"18:00"` | `"HH:MM"` |
| `daily_budget` | float \| None | `None` | `None` 或 `<=0` = **不限制预算** |
| `interests` | list[str] | `[]` | 正向偏好，与 `POI.tags` 匹配 |
| `avoid` | list[str] | `[]` | 负向偏好 |
| `pace` | str | `"normal"` | `relaxed` / `normal` / `packed`。**引擎侧消费方式**：乘以场景配置 `[pace_factor]` 得到"每天站数系数"（见 `engine/strategies.py` 的 `_per_day_top_n`） |
| `start_poi_id` | str \| None | `None` | `None` = 由引擎决定起点。**引擎侧消费方式**：`_apply_start` 在排序**之后**把该点置顶为首站（允许突破兴趣过滤；填了不存在的 ID 视为未填） |
| `top_n` | int | `6` | **每天**期望站点数（软目标，非硬约束）。多天时总数 = `top_n × days` |
| `raw_query` | str | `""` | 用户原始输入，仅留痕，不参与计算 |

`PlanRequest.from_dict()` **只取认识的字段**，未知字段忽略 —— 保证旧 JSON 不会被新字段搞崩。

## 二、POI（数据层对象，`data/pois.csv` 一行一个）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `poi_id` | str | — | 主键，全局唯一 |
| `name` | str | — | 名称 |
| `category` | str | — | 分类，口径见 `data/README.md` |
| `lat` / `lon` | float | — | 经纬度 |
| `open_time` | str | `"00:00"` | `"HH:MM"`，全天填 `"00:00"` |
| `close_time` | str | `"23:59"` | `"HH:MM"` |
| `stay_min` | int | `60` | 建议停留分钟 |
| `cost` | float | `0.0` | 人均花费，`0` = 免费 |
| `tags` | list[str] | `[]` | 兴趣标签，CSV 里用 `\|` 分隔 |
| `score` | float | `0.5` | 静态质量分 `0~1`，由数据给出 |

---

## 三、ItineraryItem（行程中的一站）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `seq` | int | — | 当天序号，从 `1` 开始 |
| `poi_id` / `name` | str | — | 站点标识与名称 |
| `lat` / `lon` | float | `0.0` | 由引擎从 POI 复制，**UI 不许直接读 CSV**，坐标从这里拿 |
| `arrive` / `leave` | str | — | `"HH:MM"` |
| `stay_min` | int | `60` | 停留分钟 |
| `cost` | float | `0.0` | 门票/餐饮花费（不含交通） |
| `transport` | Transport | 默认 | **从上一站到本站**的交通 |
| `reason` | str | `""` | 可解释性输出：为什么选它 / 为什么排这时 |

`Transport(mode, minutes, distance_km, cost)`；当天第一项的 `mode` 固定为 `"start"`。

---

## 四、DayPlan（一天的行程）

| 字段 | 说明 |
|---|---|
| `day_index` | 从 `1` 开始 |
| `items` | `ItineraryItem` 列表 |
| `total_cost` / `total_stay_min` / `total_travel_min` / `total_distance_km` | 汇总值 |

**引擎生成完必须调用一次 `refresh_stats()`**，否则汇总字段是 `0`。

---

## 五、PlanResponse（引擎唯一输出）

| 字段 | 说明 |
|---|---|
| `request` | 原样回显请求，便于复现 |
| `days` | `DayPlan` 列表 |
| `warnings` | 人类可读的降级/违规说明 |
| `metrics` | `PlanMetrics` |
| `strategy` | 使用的算法名 |
| `scenario` | 使用的场景名 |
| `generated_at` | ISO 时间字符串 |

提供 `to_dict()` / `to_json()` / `from_dict()` / `from_json()`，保证结果能落盘、能回放。

---

## 六、PlanMetrics（四维指标，全部 0~1，越大越好）

| 指标 | 含义 |
|---|---|
| `satisfaction` | 兴趣/标签匹配度 |
| `cost` | 预算友好度 |
| `time` | 时间利用率 |
| `distance` | 路程紧凑度 |
| `feasibility` | `1.0` = 零硬约束违规，有违规按条扣分 |

`overall(weights)` 做加权求和再乘 `feasibility`；权重来自场景配置的 `[weights]`。

---

## 七、Violation（硬约束违规）

`code` 取值：`BUDGET_OVER` / `TIME_WINDOW` / `CLOSED` / `DUPLICATE` / `NO_CANDIDATE`。

**铁律：违规只写进 `resp.warnings`，绝不抛异常。** 引擎在任何输入下都必须返回一个结果对象。

---

## 八、依赖方向

```
ui/  ──►  engine/  ──►  data/  ──►  *.csv
main.py / eval/  ──► 任意
```

- `engine/`、`data/`、`llm/` **禁止 import `ui`**
- `ui/` **禁止 import `data`**（坐标从 `ItineraryItem.lat/lon` 拿）
- `engine/models.py` **只 import 标准库**

自查：

```bash
grep -rn "from ui\|import ui" engine/ data/ llm/
grep -rn "from data\|import data" ui/
```

两条都必须零命中。
