# 07 · v2.0 路线图（任务大纲）

> 基线：**v1.0**（M0–M6 全部完成，262 个测试全绿，断网可演示）
> 本文只回答三件事：**2.0 要解决什么真问题、怎么拆、什么时候算做完**。
> 不是愿望清单 —— 每条都带验收口径，做不完就砍，不往里塞。

---

## 一、2.0 要解决的真问题

把 1.0 交出去之后暴露的欠账，按"用户能感知"排序：

| # | 问题 | 现在的表现 | 归属 |
|---|---|---|---|
| 1 | **导出不完整** | 只有 json / md / csv，导不进日历、发不了单文件行程单 | B |
| 2 | **时间约束不够硬** | 07:00 出发可能排到 07:30 才开门的点，靠"等开门"兜住，观感差 | B |
| 3 | **只有一座城市有实测路网** | 大连 46 点有 145 条实测；北京只估算 | B |
| 4 | **模型是"接上了"，不是"用得好"** | 固定路由表，不看成本/时延/成功率 | A |
| 5 | **只能一次性提问** | 改一句话要重跑整个请求，没有上下文 | A |
| 6 | **没有工程护栏** | 无 CI、无容器、无用量统计；全靠本地跑 | C |
| 7 | **手机上体验一般** | 桌面布局压到手机上偏挤 | D |

## 二、四条主线

```
A 智能层    ── LLM 从"能接"到"用得好"（自适应路由 / 多轮 / RAG / 视觉）

C 工程部署  ── CI / 容器 / 固定域名 / 多用户配额
D 体验质量  ── 移动端 / PWA / 覆盖率 / 性能基准
```

## 三、任务清单

优先级：**P0 = 2.0 必须有**｜P1 = 应该有｜P2 = 有余力再做

### A 智能层

| 编号 | 任务 | 为什么要做 | 验收口径 | 优先级 |
|---|---|---|---|---|
| A1 | **自适应路由**：记录每次调用的 token/耗时/成功，按"预算档"在 GLM-4.6 / DeepSeek-V4-Flash / Qwen3-Next 之间切换 | 现在路由只看文本长度，不看实际成本与稳定性；网关模型可用性会漂移 | `meta.router` 增加 `latency_ms`/`tokens`；连续 20 次调用里失败率 >20% 的模型自动降级；单测覆盖降级路径 | P0 |
| A2 | **多轮对话式调整** | 现在 `adjust` 是一次性指令，改完就断 | 支持会话 id，第 2 轮指令能引用"上一版"；会话状态落 `.cache/session/`；断网仍能走规则调整 | P0 |
| A3 | **RAG 检索**：用 `bge-m3` 给 46 个 POI 建向量索引，按自然语言召回候选 | "想找个安静能看书的地方"靠标签硬匹配会漏 | `/api/search?q=` 返回 top5 + 得分；召回率对照标注集 ≥85%；索引可重建（`tools/build_index.py`） | P1 |
| A4 | **视觉输入**：`DeepSeek-OCR` 识别课表/海报/黑板照片 → 直接生成行程草稿 | 校园场景高频（拍张课表就出行程） | `POST /api/plan` 支持 `image` 字段；单图 ≤5 张；识别失败必须降级到文本解析，不报 500 | P1 |
| A5 | 解说个性化（口吻/长度/受众） | 给新生和给家长的说明不该一样 | 场景配置加 `[narrative] tone/length`；三种口吻各一份黄金样例 | P2 |
| A6 | **可观测**：把每次路由决策写进 `meta.trace`，页面能看到"为什么用这个模型" | 现在只有最后一个决策 | 页面展开可见决策链（rule/judge/fallback + 理由）；不新增接口 | P1 |

### B 数据与算法

| 编号 | 任务 | 为什么要做 | 验收口径 | 优先级 |
|---|---|---|---|---|
| B1 | **导出全家桶**：`ics`（日历）、`geojson`（地图）、单文件 `html`（离线行程单） | `service/exporters.py` 里写着"步 8 会补"，一直没补 | 三种新格式各有单测 + 黄金样例；单文件 HTML 断网可打开、无外部依赖 | P0 |

| B6 | 评测扩面：用例 ≥20 个 + 指标回归阈值 | 现在 6 个 mock 用例，覆盖不了异常路径 | `eval/` 出回归门槛表；指标劣化 >5% 时脚本非零退出 | P1 |

## 五、2.0 的硬约束（不做就是退步）

1. **断网可演示不能退化** —— 没有 Key / 没网时，规则路径必须仍然产出完整行程与解说。
   每次加 LLM 相关功能，都要补一条"Key 为空"的测试。
2. **接口契约只增不改**（`engine/models.py` 冻结）—— 加字段给默认值，删改字段一律拒绝。
3. **`main` 上跑 `unittest` 必须全绿** —— 2.0 期间这条不放松，测试数只增不减。
4. **确定性**：同一输入两次运行，除 `generated_at` 外逐字节一致（`tools.make_demo_outputs --verify` 守着）。
5. **Key 永不出现在前端** —— 所有模型调用只经 `llm/client.py`。

### 对 E3 的具体想法（记录下来，避免走偏）

"效率最大化"的核心不是"多排几个点"，而是**承认一天里存在不同性质的时间片**：

- **连续块**（≥30 分钟）：适合进馆、吃饭、上课
- **移动片**（5–20 分钟）：只能做"不占手不占眼"的事（听播客/背单词/回消息）
- **等待片**（排队、等开门）：适合"微任务"

要做的是给每个候选元素标注 `consumes: attention | ears-only | none`，
排程时按时间片类型匹配。评测上可以定义一个可算的指标：
**"有效利用时间占比" = (有产出的时长) / (清醒总时长)**，比"满意度"更能说明问题。

## 七、风险

| # | 风险 | 信号 | 预案 |
|---|---|---|---|
| V1 | 网关模型可用性漂移（已实测：Qwen3.5-9B 90s 超时、V3.1 503） | 路由频繁 fallback | A1 的自动降级 + `tools/model_bench` 进 CI（每日定时跑） |

| V4 | 视觉/多模态引入新依赖，装不上 | 换机报 DLL 错误（已发生过） | A4 走网关的 HTTP 接口，不装本地推理库 |
