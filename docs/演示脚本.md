## 一、骨架阶段现在就能演示的三件事

1. **一条命令出结果**
   ```bash
   .venv\Scripts\python.exe main.py --request mock/case_basic.json
   ```
   展示：时间轴、每站的理由、费用、指标、提示。

2. **换算法，结果变**
   ```bash
   .venv\Scripts\python.exe main.py --strategy stub
   .venv\Scripts\python.exe main.py --strategy random
   ```
   展示：策略注册表生效，换算法不影响其他代码。

3. **有对照，才有说服力**
   ```bash
   .venv\Scripts\python.exe -m eval.baseline
   ```
   展示：`stub` 与 `random` 的指标对照表（`eval/results.md`）。
   > ⚠️ 当前 `stub` 对 `random` 的优势并不悬殊（`case_basic` 0.8309 vs 0.8204）。
   > 真正要讲"我们的算法更好"，得等 `feat/strategy-greedy` 上线后再拿表说话。
   > 骨架阶段只演示"这套对照机制跑得通"，别下"显著更优"的结论。
