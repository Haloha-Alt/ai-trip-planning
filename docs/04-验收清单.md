## 二、每次交付后的 5 分钟快检

### AC-01 改动范围是否越界

**动作**
```bat
git diff --stat
```
**期望**：改动文件数与你交待的任务相符。修 UI 却出现 `engine/` 的文件 = 越界。
**不符合**：🟠 让 AI 逐一解释每个文件为什么被改；无正当理由就 `git checkout -- <文件>` 还原。

### AC-02 冻结文件未被改

**动作**
```bat
git diff main -- engine/models.py schemas/itinerary.schema.json docs/接口契约.md docs/04-验收清单.md
```
**期望**：**完全没有输出**。
**不符合**：
- 🟡 只改了注释/docstring → 继续，但要求 AI 说明为什么必须改
- 🔴 改了字段名、类型、默认值 → 立刻 `git checkout main -- engine/models.py`，并按 `02` T00 开新对话，走"改字段须升 v2"流程

> **已授权的例外（契约修订 v1.2 / 2026-10-27）**：本次在每个 dataclass **末尾追加**了带默认值的字段，
> 并同步了 `docs/接口契约.md` + `schemas/itinerary.schema.json` + 本文件 AC-50 的键列表。
> 判定口径不是"有没有 diff"，而是 **`git diff` 里有没有删除行**：
> ```bat
> git diff main -- engine/models.py | findstr /R /C:"^-"
> ```
> 除 `CONTRACT_VERSION` 之类注释行外**没有字段定义被删除**即为合规。`PlanMetrics` 必须零改动。

### AC-03 有没有硬编码业务数值

**动作**
```bat
grep -rnE "元|大连|预算 [0-9]|星海|150" engine/ ui/render.py main.py
```
**期望**：零命中（`engine/config.py` 允许出现字段名，不允许出现具体数值）。
**不符合**：🟠 把数值挪进 `config/scenarios/*.toml`，代码里改成从 `cfg` 读。

### AC-04 测试是否仍全绿

**动作**
```bat
.venv\Scripts\python.exe -m unittest discover -s tests -t . 2>&1 | tail -3
```
**期望**
```
Ran 43 tests in 0.0xx s
OK
```
（数字随你新增用例变化，关键是最后一行必须是 `OK`；出现 `FAILED` 即不通过。）
**不符合**：🔴 测试红 = 不能提交。先看是哪一条，对照本文件第五章。

### AC-05 依赖方向

**动作**
```bat
grep -rn "from ui\|import ui" engine/ data/ llm/
grep -rn "from data\|import data" ui/
```
**期望**：两条都零命中。
**不符合**：🟠 说明分层被破坏。UI 要清缓存就用 `engine.planner.clear_caches()`，不要直接 `from data.loader import ...`。

### AC-06 提交信息是否合规

**动作**
```bat
git log --oneline -5
```
**期望**：`类型: 中文描述`，类型 ∈ `feat|fix|docs|chore|test|refactor`。例：`fix: 修复 9 处死链与硬点`。
**不符合**：🟡 `git commit --amend -m "..."`（还没 push 时）；已 push 就别改历史，下次注意。

### AC-07 有没有偷偷加依赖


**期望**：无输出。
**不符合**：🟠 本项目坚持零新增依赖。真需要就看 `01` 2.4 的装库流程，**并向队友说明**。

## 三、功能验收

### AC-10 CLI 三种输入都能跑

**动作**
```bat
.venv\Scripts\python.exe main.py
.venv\Scripts\python.exe main.py --request mock\case_basic.json
.venv\Scripts\python.exe main.py --query "想走走自然类的地方，预算 100 元"
```
**期望**：三条都打印 `场景 demo | 策略 stub | 生成于 ...`，并落盘 `outputs\plan_demo_stub.json`。第三条应能识别出"自然"和预算 100。
**不符合**：🔴 报 Traceback → 看第六章"怎么读报错"。

### AC-11 三个 mock 用例回归（**最常用的一条**）

**动作**
```bat
.venv\Scripts\python.exe main.py --request mock\case_basic.json
.venv\Scripts\python.exe main.py --request mock\case_tight.json
.venv\Scripts\python.exe main.py --request mock\case_empty.json
```
**期望**

| 用例 | 站点数 | 必须出现的提示 | 绝不允许 |
|---|---|---|---|
| `case_basic` | 3～5 | 无 | — |
| `case_tight` | 1～2 | `BUDGET_OVER` | 崩 |
| `case_empty` | **> 0** | 无 | **空行程（站点 0）** |

> ⚠️ `case_empty` 的直觉是反的：它排除了几乎所有标签、兴趣词也不存在，
> 但引擎会**故意放宽到全部 POI** 再排几站。所以"站点 > 0"才是正确行为。
> 如果它变成 0 站，说明 `_candidate_pool` 里的放宽分支被改坏了。

三条都必须打印 `已保存：...outputs\plan_demo_*.json`。

**不符合**：
- 🔴 报 Traceback → 回滚本次 commit
- 🟠 `case_empty` 站点 0 → 查 `engine/strategies.py` 的 `_candidate_pool` 末尾 `if not pool: pool = list(pois)`
- 🟠 `case_tight` 没有 `BUDGET_OVER` → 查 `engine/constraints.py` 的预算判断，或 `mock/case_tight.json` 的 `daily_budget` 被改了

### AC-12 多天输出

**动作**
```bat
.venv\Scripts\python.exe main.py --days 2 --top-n 2
```
**期望**：出现两段 `[第 1 天]` 和 `[第 2 天]`，每段 `站点 2 个`。
**不符合**：🟠 只有一天 → 查 `engine/strategies.py` 的 `_build_days` 是否被回退成 `days=[day]`。

### AC-13 节奏（pace）真的生效

**动作**
```bat
.venv\Scripts\python.exe main.py --pace relaxed --top-n 3
.venv\Scripts\python.exe main.py --pace normal  --top-n 3
.venv\Scripts\python.exe main.py --pace packed  --top-n 3
```
**期望**：站点数依次 **2 / 3 / 4**（递增）。
**不符合**：🟠 三者相同 → 查 `engine/strategies.py` 的 `_per_day_top_n` 和 `config/scenarios/demo.toml` 的 `[pace_factor]`。

### AC-14 起点硬指定

**动作**
```bat
.venv\Scripts\python.exe -c "from engine.models import PlanRequest; from engine.planner import plan; r=plan(PlanRequest(top_n=3, start_poi_id='P007')); print(r.days[0].items[0].poi_id)"
```
**期望**：输出 `P007`。
**不符合**：🟠 输出别的 ID → 查 `_apply_start` 是否在排序**之后**调用（在 `_build_days` 里）。

### AC-15 换场景后指标按新场景算

**动作**：等 `feat/data-real` 分支有了第二个场景后
```bat
.venv\Scripts\python.exe main.py --scenario campus --top-n 3
```
**期望**：满意度、预算友好度与 `--scenario demo` 不同；不出现莫名其妙的 `CLOSED` 警告。
**不符合**：🟠 满意度恒为 0 或全出现 `CLOSED` → `engine/constraints.py` 里 `load_pois()` / `get_poi()` 又漏传 `cfg` 了。

### AC-16 UI 控件的覆盖语义

**动作**（界面）
1. 左边侧边栏**什么都别动**，点「生成行程」
2. 展开「解析出的请求（PlanRequest）」
3. 看 `daily_budget` 与 `pace`

**期望**

| 情形 | `daily_budget` | `pace` |
|---|---|---|
| 不动控件，文本含"预算 100 元，别太赶" | `100.0` | `relaxed` |
| 手动把预算拖到 200 | `200.0` | — |
| 手动把预算拖回 0 | `null`（= 不限制） | — |

**不符合**：🟠 不动控件时 `daily_budget` 是 `null` → `ui/app.py` 又变回无条件覆盖了，检查 `_touched(...)` 判断。

## 五、评测验收

### AC-30 `results.md` 的前后差异

**动作**
```bat
git stash push eval/results.md 2>nul
.venv\Scripts\python.exe -m eval.baseline
git diff eval/results.md
```
**期望**：逐行比对，**每一处变化都能说出原因**。
- 只改了 `random` 那一行 → 正常（随机基线本来就该有波动，但本项目已固定种子，正常情况下应为**零差异**）
- `stub` 那一行变了 → 🟠 引擎行为被改了，必须解释
**不符合**：🟠 说不出原因 → 回滚本次改动，重新只改一件事。

> 每次跑完 baseline 都要**单独提交一次**：
> `git add eval/results.md && git commit -m "chore(eval): 更新基线结果"`

### AC-31 新算法确实优于随机基线

**动作**
```bat
.venv\Scripts\python.exe -m eval.baseline
```
**期望**：在多数用例上，新策略的 **总分** > `random`。
当前基线（2026-10-27）：

| 用例 | stub | random | 结论 |
|---|---|---|---|
| `case_basic` | 0.8309 | 0.8204 | stub 优 |
| `case_tight` | 0.6000 | 0.4200 | stub 明显优 |
| `case_empty` | 0.3224 | 0.3397 | random 偶然更高（满意度都是 0，比的是花费） |

**判读口径**：看**总体**，不看单个用例。`case_empty` 这种"全员 0 满意度"的用例不具区分度。
**不符合**：🟠 新算法在所有用例上都不如 random → 算法或指标有问题，别急着写报告。

### AC-44 界面默认算法与场景配置一致（**容易漏**）

**动作**：打开界面，**什么都别动**，看侧边栏「算法」下拉框默认选中项；再点「生成行程」，对比站点顺序。

**期望**：默认选中 `demo.toml` 里 `default_strategy` 的值（当前 `stub`），**不是 `random`**；
站点顺序与命令行完全一致：

```bat
.venv\Scripts\python.exe main.py --request mock\case_basic.json
```
两边都应是 `占位点05 → 占位点01 → 占位点08`（09:00 / 10:00 / 11:41）。

**不符合**：🔴 默认是 `random` → `ui/app.py` 又写成 `index=0` 了。
原因：`available()` 是**字母序**，`['random','stub']` 的第一个是 random（故意做笨的对照组），
默认必须用 `index=_names.index(cfg.default_strategy)`。

> 这条是真实踩过的坑：只验"页面能渲染出表格"是不够的，还要验"默认选的是哪个算法"。
> 否则界面一直跑随机基线，站点顺序与命令行对不上，还会被误判成算法有 bug。

### AC-43 没有坐标也不崩

## 九、"不符合"怎么办（按编号查）

| 编号 | 最可能的原因 | 修法 |
|---|---|---|
| AC-02 | AI 想"顺便优化"数据结构 | `git checkout main -- engine/models.py`，开新对话（`05` D6） |

### 怎么读报错（简版）

1. **从上往下读是错的**，Python 的报错要**从最后一行往上读**：最后一行是"什么错"，倒数第二段是"在哪一行"。
2. 看到 `File "D:\projects\ai-trip-planner\engine\strategies.py", line 132` → 直接跳过去看那一行。
3. `KeyError: '未知策略 xxx'` 是**项目自己抛的**（`main.py` 已捕获并返回码 2），不是 bug —— 检查 `--strategy` 拼写。
4. `ModuleNotFoundError: No module named 'xxx'` → 九成是解释器不对，见 `01` 6.1。
5. 拿不准就把**完整 traceback 原文**贴给 AI，用 `02` T10。
