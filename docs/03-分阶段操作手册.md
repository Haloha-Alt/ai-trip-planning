## 一、怎么用这本手册

### 1.1 一个大分支 = 一个功能模块 + 一条 git 分支 + 一套提示词 + 一套验收

一条分支只干一件事。干完 → 验收 → 合并 → 删分支。**不许在一条分支里顺手做第二件事。**

### 1.2 每一节的固定八段

| 段 | 回答什么 |
|---|---|
| 目标 | 做完之后能多出什么能力 |
| 前置条件 | 上一节是否已完成、测试是否全绿 |
| 建分支 | 可复制的命令 |
| 提示词 | 用 `02` 的哪几张卡 |
| AI 产出后看什么 | 人工必看的 3~5 项（AI 不会主动告诉你） |
| 验收 | 跑 `04` 的哪几条 |
| 提交与合并 | commit message 要点 + 合并命令 |
| 常见翻车 | 这一节特有的坑 |

### 1.3 分支清单

|---|---|---|
| 0 | （直接推 main） | ✅ 已完成 |

### 1.4 开工前的 60 秒自检（每次都要做）

```bat
cd /d D:\projects\ai-trip-planner
git status --short
git branch --show-current
git log --oneline -3
.venv\Scripts\python.exe -m unittest discover -s tests -t . 2>&1 | tail -3
```

**通过标准**：① `git status` 输出为空 ② 分支名是你要工作的那条 ③ 最近 3 条 commit 你能看懂 ④ 最后一行是 `OK`。
任意一条不满足 → 先解决，别开始写代码。

### 3.8 常见翻车

| 现象 | 原因 | 修法 |
|---|---|---|
| 动预算控件没反应 | `args` 传成了字符串 | 必须是元组 `args=("budget",)` |

## 四、分支 2 · `feat/data-real`（换真实数据）

### 4.1 目标
用真实 POI 与真实场景替换占位数据，**Python 代码零改动**。

### 4.2 前置条件
分支 1 已合并；测试全绿；助教已答复场景锁定问题（`需求说明书` Q7）。

### 4.3 建分支


### 4.4 提示词
`T00` → `T01`（先让 AI 读懂 `data/loader.py` 的容错规则）→ `T02` → `T06` → `T15`

### 4.5 AI 产出后必看什么

1. **列名一个都不能变** —— 变了代码就取不到值（`AC-20`）
2. **编码是 UTF-8 带 BOM** —— 用 Excel 另存时选「CSV UTF-8」
3. **`tags` 用竖线分隔** —— 用逗号会让整列变成一个标签
4. **`open_time` / `close_time` 是 `"HH:MM"` 且补零** —— Excel 会把 `09:00` 自动变成时间格式，读出来是 `0.375`
5. **`interest_alias` 右边的值必须真的出现在 CSV 的 `tags` 里** —— 否则兴趣永远匹配不上

### 4.6 验收
`AC-20`、`AC-21`、`AC-22`、`AC-23`、`AC-15`、`AC-11`、`AC-04`

### 4.7 提交与合并（3 个 commit）

1. `feat(data): 替换为真实 POI 数据`
2. `feat(config): 新增 campus 场景与兴趣词映射`
3. `docs(data): 更新字段口径与打分数值说明`

```bat
git push -u origin feat/data-real
```

### 4.8 常见翻车

| 现象 | 修法 |
|---|---|
| 页面白屏并打印 `[error] ... 解析出 0 条` | 编码错或列名被改，按 `AC-20` 查 |
| 所有兴趣都匹配不上 | `interest_alias` 右边的值不在 `tags` 里，或 `tags` 用了逗号 |
| 时间全变成 `00:00` | Excel 存成了时间格式，先把列设成"文本"再填 |
| 下拉框里多出一个 `template` | 正常，它是模板不是场景，忽略 |
| 换数据后测试红 | 理论上不该红（已改数据驱动）；若红说明数据本身违反硬约束，按 `AC-04` 看是哪条 |

## 十二、通用急救包

### 12.1 冲突怎么解

```bat
git status --short
```
看到 `UU 文件路径` 就是冲突。打开该文件，会看到：

```
<<<<<<< HEAD
（你这一边的版本）
=======
（对方那一边的版本）
>>>>>>> origin/main
```

处理三步：① 决定留哪边（或融合）② **把三行标记全部删掉** ③ `git add 文件路径` → `git commit`。

判定表：

| 冲突文件 | 通常留哪边 |
|---|---|
| `eval/results.md` | 谁最后跑过 baseline 就留谁的（它是自动生成的，重新跑一遍即可） |
| `README.md` | 谁的描述更准确留谁；两边都改了就手工融合 |
| `engine/models.py` | **两边都不许改**，出现冲突说明有人违规，先 `git checkout main -- engine/models.py` |
| `data/*.csv` | 通常不该冲突（谁换数据谁负责），冲突说明两人都换了，要商量 |

### 12.2 改错了，回到上一个 commit

```bat
git restore .                 :: 丢弃工作区未提交的改动
git restore --staged .        :: 连暂存一起丢
git reset --hard HEAD~1       :: 回到上一个 commit（**已提交**的改动才会被丢，慎用）
```
已经 push 了就**别 reset**，改用 `git revert <sha>`（生成一个反向提交，历史保留）。

### 12.3 提交到错分支了

```bat
git log --oneline -1                  :: 记下这个 commit 的 sha
git switch 正确的分支
git cherry-pick <sha>
git switch 错的分支
git reset --hard HEAD~1
```

### 12.4 推送被拒（non-fast-forward）

```bat
git pull --rebase origin main
```
有冲突按 12.1 处理，然后 `git rebase --continue`，最后 `git push`。

**绝对不要**用 `git push --force` 去覆盖队友的提交。

### 12.5 忘了开分支，在 main 上改了一堆

```bat
git switch -c feat/忘了开的分支    :: 把当前改动带到新分支
git switch main
git reset --hard origin/main       :: main 回到远端状态（改动已安全带到新分支）
```
