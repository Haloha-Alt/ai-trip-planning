## 三、三条硬规则

1. **共同文件加锁**：★ 文件要改，先在项目消息里说一句，对方回 OK 才动。改完立刻告诉对方"已提交，请用 `mock/case_basic.json` 测一下"。
   > "项目消息"具体指什么、怎么说、什么时候该另开一个对话，见 `05-LearnBuddy协作节奏.md` 第七章（三行决策记录）。
2. **契约冻结**：`engine/models.py` 定稿后只许**加带默认值的新字段**，不许改字段名、改语义、删字段。要改就得走 v1 → v2，并同步 `docs/接口契约.md` + `schemas/*.json` + `mock/*.json`。
3. **单向依赖**：`ui/ → engine/ → data/`。`engine/`、`data/`、`llm/` 里**禁止 import ui**；UI **禁止直接读 CSV**（坐标从 `ItineraryItem.lat/lon` 拿）。

自查命令（甲在每个里程碑跑一次，必须零命中）：

```bash
grep -rn "from ui\|import ui" engine/ data/ llm/
grep -rn "from data\|import data" ui/
```

## 四、每日节奏

1. 开工前 `git log --oneline -3` 看对方昨天做了什么
2. 改自己的文件，跑测试
3. 提交（Conventional Commits 格式）
4. 在项目消息里发 3 行站会：昨天做了什么 / 今天要做什么 / 卡在哪
5. 收工前 `git push`（**不要攒**，本地只有一份历史，见 `00-总纲与路线图.md` 风险 R1）
6. 有结论就落盘（改过的字段语义、否掉的方案、踩过的坑），格式见 `05-LearnBuddy协作节奏.md` 第七章

## 五、贡献留痕

每个 Python 文件头统一写三行：

```python
# @author: 甲
# @reviewer: 乙
# @since: 2026-10-27
```

`git log` 本身就是最硬的个人贡献证明，**不要用别人的账号提交**。
