# 18 · 更完整的校园地图，以及"额度送福利"该怎么用

> 版本 v1.0 ／ 2026-11-03 ／ 回答三件事：
> **① 为什么可以不走学校授权（只有高德行不行）；② 现在的地图能有多完整；③ 模型还能干什么，包括"送福利"。**

---

## 一、先回答那句质问：只有高德行不行？

**行。而且对你现在这个阶段，只走高德是最优解。** 但要分清"能用"和"最详细"：

| 目标 | 高德够不够 | 说明 |
|---|---|---|
| 排出行程、算时间算钱 | **完全够，而且更好** | 高德有 GCJ-02 坐标、有 API、有实测步行耗时，比校方图更规范 |
| 地图上"看到学校长什么样" | 够（卫星图能看清楼顶、操场、道路） | 你要的"有辨识度"已经达成 |
| **看清每栋楼的名字、楼内设施、内部小路** | **不够** | 高德只给"点"，不给"面"；校内楼大量不收录 |
| 官方背书（答辩时"这图哪来的"） | 不需要 | 高德公开授权，标注即可 |

### 1.1 那封邮件到底要不要发？

| 你的目标 | 要不要发邮件 |
|---|---|
| 演示能用、答辩能过、能扩展到其他学校 | **不用**。高德路线两小时一所，合规且可复现 |
| 想做"最完整齐全详细"的校园图（楼栋级） | **发了更省事，但不是唯一途径**（见第二节第三条） |

**结论**：邮件从"前置依赖"降级成"顺手发一封"。发了是加分（官方背书 + 楼栋图），不发也不欠什么。
如果你已经觉得麻烦——**别发**，把时间花在第二节第三条上，效果一样，主动权还在你手里。

## 二、要"最完整齐全详细"，有三条路

| 路 | 能做到多细 | 一次性成本 | 维护 | 合规 | 依赖别人 |
|---|---|---|---|---|---|
| **① 高德全量 POI**（已做） | 点级：校内 112 个真实点位（宿舍/食堂/场馆/打印/快递/超市/学院楼） | **已完成** | 加城市时重跑一次 | ✅ | 否 |
| **② 自己描楼栋轮廓** | **楼栋级**：把 20–30 栋楼的轮廓描成多边形，叠在卫星图上 | 每栋 40 秒 ≈ 20 分钟 | 楼变了自己改 | ✅ 自绘 | 否 |
| ③ 校方瓦片 | 测绘级：含屋顶、连廊、内部小路 | 一封邮件 + 1–5 天等待 | 无需维护 | ✅ 仅授权范围 | **是** |

### 2.1 我的建议：走 ① + ②，第三条当彩蛋

**②怎么做的**（这条最关键：不用等任何人）

1. 用高德 JS API 打开卫星图，缩放 18；
2. 用 `AMap.Polygon` 的编辑模式，沿屋顶描一圈（图书馆这种大屋顶 40 秒，小楼 15 秒）；
3. 存成 `data/cities/dalian/buildings.geojson`：`{"name":"伯川图书馆","poi_id":"DL003","polygon":[[lon,lat],...]}`；
4. 页面上按 `poi_id` 给轮廓上色：行程里的站点高亮，其余淡灰。

**这样做出来的效果，比校方瓦片更适合你**：
- 你的图**只有 20 栋楼**，信息密度低、对比强，而校方图信息很密、缩略图上看不清；
- 能**按行程高亮**（校方瓦片做不到，它是死的图片）；
- 断网也能画（本地 geojson，不用等瓦片）；
- 而且——**这是"我们自己做了一张校园图"，答辩时比"用了学校的图"更硬气**。

> 我可以再给你一个"描楼工具"（沿卫星图点几个点，自动闭合成多边形并导出 geojson），
> 跟之前的配准器同一套路。需要就说一声。

## 四、"送福利"怎么做才不亏

### 4.1 先算一笔账：额度不是瓶颈

| 环节 | 典型 token | 次数/人/天 | 月成本量级 |
|---|---|---|---|
| 解析（fast 模型） | 500–800 | 3 | 可忽略 |
| 解说（default） | 500–900 | 3 | 可忽略 |
| 冲突取舍（reasoning） | 800–1200 | 0–2 | 可忽略 |

网关额度 1500 元/月，按这个量级，**真实瓶颈不是钱，是并发和滥用**。
所以"送福利"的正确姿势不是"省着用"，而是：**大方地送，但把闸门装在入口**（`ACCESS_CODE` + 每设备每日次数）。

### 4.2 四个"福利"设计（都能落地，成本几乎为零）

| 福利 | 规则 | 为什么送这个 |
|---|---|---|
| **每天 3 次"深度规划"** | 带模型解析/解说/取舍的算深度；用完后自动降级为"规则模式"（无限次） | 用户不会觉得被卡住——**只是从"聪明"降到"够用"**，而且顺带演示了降级链 |
| **新生的第一份行程** | 首次访问送一次"完整版"：一句话 → 行程 + 打印版 PDF + 三条老生提示 | 场景天然、传播性强（新生会转给同学） |
| **分享得额度** | 把行程链接发给同学，双方各 +1 次深度规划 | 增长闭环，且不花额外成本 |
| **周二/周四"免额度日"** | 特定时段全部走模型 | 制造"今天可以用满"的期待，也方便你控制总量 |

### 4.3 一句话设计原则

> **把"模型的聪明"做成稀缺但随时够用的东西**：
> 免费无限次给"够用"，每天限量给"聪明"，再留一个分享的口子让人自己赚。
> 这样既不烧额度，又让人觉得"这产品有诚意"。

## 六、关于"无限额度"：可以做，但闸门要装在入口

你说了"用的人不多，直接无限"。技术上完全可以——现在的额度瓶颈根本不在钱：

| 项 | 估算 |
|---|---|
| 单次解析 token | 500–800 |
| 单次解说 token | 500–900 |
| 一次完整规划（解析+解说） | ≈ 1500 token |
| 网关额度 1500 元/月 ÷ 这个量级 | **够几万次**，且用不满 |

所以"无限额度"的正确实现不是"不做限制"，而是**把限制从"次数"换成"入口"**：

| 层 | 怎么做 | 为什么 |
|---|---|---|
| 入口 | `ACCESS_CODE` 仍然设（一个口令，同学之间传） | 防的不是同学，是爬虫/扫描 |
| 单请求 | 上限仍是 **≤3 次模型调用**（解析 / 解说 / 取舍） | 防的是"一句话触发十次调用"的死循环 |
| 失败 | 模型超时 → 自动降级规则，页面标"规则模式" | 让"慢"看起来像"降级"，不像"坏了" |
| 监控 | `/api/llm` 面板看最近 8 次的耗时与成败 | 额度被异常消耗时能立刻看见 |

> 一句话：**对人不设限，对程序设限。**

## 七、多套 UI 与"让模型生成界面"

三条路，成本差很多：

| 做法 | 成本 | 风险 | 建议 |
|---|---|---|---|
| **① 三套主题（纸/暗/图）** | 已做过原型（`design/mock-multitheme.html`） | 低 | ✅ 做主路径 |
| **② 模型生成主题 token** | 中（一个 schema + 校验 + 预览） | 中：模型会给对比度不足的配色 | 作为彩蛋 |
| ③ 模型生成整页 HTML | 高 | **很高**：不可控、无法测试、离线崩 | ❌ 不做 |

**②怎么做才安全**：不要让模型写 CSS，让它**填一张表**——

```json
{"name":"夜跑","bg":"#0f1115","card":"#171b22","ink":"#e8eef5","accent":"#4ea1ff",
 "muted":"#7b8794","rule":"#242b35","font":"sans","density":"compact"}
```

前端拿到这 7 个颜色 + 2 个枚举，自动生成 CSS 变量；再用一条规则卡住下限：
**对比度 < 4.5:1 就拒绝并回退到内置主题**（服务端算，不许前端"看着还行"）。

这样"个性化"是真的，但**不可能生成一个坏掉的界面**——这就是"给模型自由，但给它画好笼子"。
