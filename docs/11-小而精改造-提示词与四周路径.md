## 一、先把"特色"定死，再谈功能

### 1.1 三个候选，各自代价

| 方向 | 一眼看到什么 | 成本 | 风险 |
|---|---|---|---|
| **A 时刻表纸**（推荐） | 一张米白纸，一条纵轴，站块的高度就是停留时长，缝隙就是在途，点纹就是等开门；右侧一行行写着"为什么是它" | 中（纯前端 + 一个 trace 字段） | 需要忍住不做花哨动效 |
| B 编译器诊断风 | 把行程当编译结果：等宽字体、行号、`warning` 逐条列出、红字指出冲突 | 低 | 太硬核，目标用户是同学不是程序员，第一次看会懵 |
| C 真地图优先 | 底图占 2/3，行程浮在上面 | 高（Key + 域名白名单 + 样式受限） | **辨识度其实是高德的，不是你的**；Key 一断就空 |

**选 A。** 三条理由，都能在答辩时直接说出口：

1. **时间轴是这个项目唯一"别人没有"的东西。** 市面上的行程工具默认给"卡片列表"，而你的核心资产是"时间可计算"——把它画成轴，能力就变成了长相。
2. **它不依赖任何外部服务。** 断网、没 Key、答辩机不让联网，照样满分。这是 v1.0 攒下的底子，别在新界面上丢掉。
3. **它把三句卖点变成了三种视觉。** 块高 = 停留（可计算）、旁注 = 为什么（可解释）、空白带 = 没排进去的点（可核查）。不用写一个字解释，评委自己看出来了。

B 的"诊断感"不单独做页面，嫁接到 A 的旁注上（红框小标签 + 规则代码，见样张）。C 降级成"有 Key 就在旁注栏底部放一张小图"，没有 Key 就整块不出现。

> 样张已生成：`design/mock-a-timetable.html`（双击即开，无任何依赖）。
> 它就是后面所有提示词的"目标形态"——**给 AI 看文件，不要用形容词描述**。

### 1.2 设计契约（钉死，四周内不改）

| 项 | 定值 |
|---|---|
| 纸 | `#faf8f3`；极淡横线（活页纸质感），透明度 ≤3% |
| 墨 | 主 `#1c1b19`／次 `#5b574e`／弱 `#8f8878`／线 `#e2dccd` |
| 强调色 | **只有一个**：朱红 `#b23a2f`（用于：规则代码标签、站序、冲突金额） |
| 字体 | 标题宋体（Songti SC / Noto Serif），正文黑体，**所有时间与金额等宽（mono）** |
| 比例规则 | 站块高度 = 停留分钟 × 固定像素比，**一像素都不许为了好看压缩** |
| 负空间规则 | 每个"没排进去的点"必须在页面上有位置，并带规则代码（`BUDGET_OVER` 等） |
| 四个不许 | 不许堆卡片阴影／不许渐变／不许图标字体／不许引入框架或 CDN |

### 1.3 怎么证明"有特色"不是自嗨（三个外部检验）

| 检验 | 做法 | 通过标准 |
|---|---|---|
| 5 秒测试 | 截图给没听你讲过的同学看 5 秒 | 他能说出"这是一天的行程安排" |
| 盲选测试 | 把你的截图和 3 个行程 App 截图混在一起 | 别人能挑出"哪个是学生做的" |
| 一句话测试 | 让同学用一句话描述你的界面 | 话里出现"时间轴 / 时刻表 / 行程单" |

三个都过，才叫特色；只过第一个，那叫"能用"。

## 二、提示词怎么设计（四条原则 + 一个结构）

### 2.1 四条原则

1. **一卡一事。** 一张卡只产生**一个能被截图证明的变化**。想同时改骨架和配色，拆成两张卡。
2. **每卡带"可运行判据"。** 不许出现"看起来不错／更美观了"这种验收。要么是命令（`node _render_check.js`），要么是断言（块高误差 < 2px），要么是"截这张图给我看"。
3. **每卡写"禁区"。** 明确列出**不许碰的文件**和**不许顺手加的功能**。AI 最常犯的错不是写错，是**多写**——这是"小而精"最大的杀手。
4. **每卡给"反面例子"。** 写下这张卡最常见的跑偏方式。实践里这一行的价值高于正文。

### 2.2 一张卡固定五段（沿用 02 的槽位，加强后两段）

| 段 | 写什么 |
|---|---|
| 目标 | 一句话，可验收 |
| 贴什么 | 具体文件路径 / 片段 / 现状截图 |
| 正文 | 可直接复制的话 |
| 验收 | 命令、断言或"截哪张图" |
| 禁区＋反模式 | 不许改什么 + AI 最可能怎么跑偏 |

### 2.3 UI 任务额外要三条（和写后端不一样）

- **先出变体再选**，不要一次做到底。三个样张的成本 ≈ 一个"做完再返工"的成本。
- **一个 commit 一个可见变化**，方便单点回滚；UI 改动最怕"整页重写"，回滚等于重做。
- **每张卡跑完必须两件事**：`node _render_check.js`（已有 13 项断言）＋ 一张 1200px 宽截图存 `design/shots/`。

### 2.4 三条 UI 验收断言（写进每一张卡的"验收"段）

```text
① 375px 宽无横向滚动（document.scrollWidth <= 375）
② 每个站块高度 |h - (leave-arrive)*PPM| <= 2px
③ 页面上"没排进去"的条目数 == 后端 warnings 条数
```

## 三、提示词卡 T20–T31

> 用法：从 T20 开始，做完一张再做下一张。每张卡开头先跑 `02` 的 1.4 固定上下文包。

### T20 · 视觉样张三选一（只出静态，不写业务代码）

**用在哪**：第一步，也是唯一一次"允许发散"。
**贴什么**：`mock/case_multiday.json` 的真实输出（别让它编数据）。
```text
只读 + 只出静态样张。不要改 web/index.html，不要碰任何 .py 文件。

【目标】用同一份真实行程数据，做 3 个视觉风格完全不同的静态页面，我挑一个。
【数据】用 mock/case_multiday.json 的真实输出（时间、金额、站名都照抄），不许编数字。
【三个方向】
  A 时刻表纸：米白纸底 + 墨黑 + 单一朱红强调色 + 等宽数字；站块高度=停留时长
  B 仪表盘：深色底 + 卡片堆叠 + 环形指标
  C 地图优先：底图占 2/3，行程浮在上面
【约束】每个都是单文件 HTML；无 CDN、无字体文件、无框架；每个 < 60KB；断网可开
【输出】design/mock-a.html、mock-b.html、mock-c.html，每个后面写 3 行：
        它最像什么产品 / 它最强的 1 点 / 它最弱 1 点
【自检】三份都能双击打开；都没有横向滚动；数字都没溢出容器
最后不要替我选，把选择留给我。
```
**验收**：3 个文件都能打开；把三个并排截图发我。
**禁区＋反模式**：不要直接改真页面——那你就失去了对比的机会；也不要在三个样张里共用同一套 CSS（那样看不出差别）。

### T21 · 骨架重排：四页签 → 一条主轴 ＋ 一条旁注栏

**用在哪**：定调之后第一张真正落地的卡。
**贴什么**：`web/index.html` 全文 + 选定样张全文。
```text
改 web/index.html 的布局层，不改任何 JS 逻辑函数、不改 API 调用。

【目标】把现在的"四页签（行程表/时间轴/地图/算法对比）"改成：
  顶部：一行输入条（一句话需求 + 重排按钮）
  中部：左=时间轴主轴（唯一主视图）｜右=旁注栏（为什么这么排）
  底部：权重滑杆 + 指标条
  "行程表"降级为轴下方可折叠的表格；"算法对比"改成一个按钮弹出
【约束】只动 HTML 结构与 CSS，不许新增 DOM 层超过两层；
        不许删除任何已有 id（tl/list/map/compare 的容器保留，先 hidden）
【验收】页面能显示 mock 数据；node _render_check.js 13 项仍全绿；
        截一张 1200px 宽的图给我
【禁区】不许顺手改配色（配色是下一张卡）；不许动 fetch 逻辑；不许加依赖
```
**反模式**：AI 会"顺手"把四个页签的渲染函数都重写——明确说"渲染函数一行都不许动"。

### T22 · 让轴说实话：块高 = 停留时长

```text
只改时间轴的绘制函数（renderTimeline 一带）。

【目标】轴上每个站块的高度必须等于 (leave - arrive) × PPM，PPM 写成常量放在顶部；
        在途用斜纹、等待用点纹、停留用白底 + 15 分钟一格的内横线
【数据】arrive/leave 都是 "HH:MM"，转换成分钟再算；跨零点先不支持，遇到就报错不要猜
【约束】不许引入时间库（dayjs/moment 一律不加），用 Date 或手写分钟转换
【验收】三个断言：
  ① 每个站块 |h - (leave-arrive)*PPM| <= 2px（写成 console.assert）
  ② 一天的轴总高 == (末站 leave - 首站 arrive)*PPM + 边距
  ③ 375px 宽下无横向滚动
  并且截一张图，图上要能看见"等的 12 分钟"是一段点纹
【禁区】不许为了"看起来满"去压缩或拉伸块高 —— 这是本项目的底线之一
```
**反模式**：它会把块高写成 `min-height:120px` 之类，看起来整齐，实际上把"可计算"这个卖点抹掉了。

### T23 · 后端最小 trace：三类理由，只加字段不改契约

**用在哪**：旁注栏的数据来源。**这是唯一需要动 Python 的一张卡。**
```text
只改 engine/planner.py（或 strategies.py 里的选点处），加一个"决策记录"。

【目标】给 PlanResponse.meta 增加 trace（list[dict]），每条只记三件事：
  {"kind":"pick","poi_id":"...","why":"命中兴趣:图书馆","num":{"walk_min":8,"wait_min":12}}
  {"kind":"skip","poi_id":"...","why":"超预算 8 元","rule":"BUDGET_OVER"}
  {"kind":"route","role":"fast","model":"...","source":"rule","latency_ms":312}
【约束】engine/models.py 只许【新增带默认值】的字段，既有字段一个都不许改；
        trace 必须是纯数据（dict/list/str/int/float），不许放对象；不许调用大模型
【验收】① 新增单测：同一次 plan() 两次调用，trace 除时间戳外逐字节一致
        ② 294 个测试仍全绿 ③ 随机抽一条 case_multiday 的 trace 贴给我看
【禁区】不许把 trace 拼成给人看的中文长句（那是前端的事）；不许为此装依赖
```
**反模式**：它会去"多问一次大模型"来生成理由——那会吃网关额度，而且两次结果不一样。理由必须来自规则本身。

### T24 · 旁注：为什么选它

```text
只改旁注栏的渲染，不动轴、不动后端。

【目标】每个站块右侧对齐一条旁注：朱红小标签（命中兴趣/顺路/预算内）+ 一句带数字的理由
【数据】只读 meta.trace 里 kind=pick 的条目，不许自己再算一遍
【约束】旁注与站块的垂直位置误差 <= 2px；条目超过 1 行时最多折 2 行，超出省略
【验收】截一张图；并且把鼠标移到任意一条旁注上，能看到对应站块高亮（加 class 即可）
【禁区】不许在旁注里写"根据算法计算得出"这种空话——理由里必须出现数字或标签名
```
**反模式**：它会写"该地点符合您的偏好"——这类话等于没说，验收里明确要"出现数字或标签名"。

### T25 · 负空间：为什么没选它

```text
在轴下方加"没排进去的"区块。

【目标】遍历 meta.trace 里 kind=skip 的条目，逐条渲染：点名 + 一句话原因 + 规则代码
      （规则代码用等宽字体 + 朱红细边框，像编译器的错误码）
【约束】条目数必须等于 warnings 条数，多一条少一条都算错；空的时候显示"没有点被跳过"
【验收】把 case_multiday 的页面截图给我，我要看到至少 2 条 skip 且代码各不相同
【禁区】不许把这些条目做成"温馨提示"的柔和样式 —— 冲突就该刺眼
```
**反模式**：它会合并同类项（"3 个点因预算原因跳过"），那样就失去了"逐条可核查"的价值。

### T26 · 三档权重与实时重排

```text
加三根滑杆（省钱/省时/舒适）+ 三档预设按钮。

【目标】拖动滑杆 → 调 /api/plan（带 weights 覆盖）→ 轴重排；拖动过程中不许发请求，
        松手后 300ms 防抖再发；重排时在轴顶部显示"正在重算"，不许整页闪烁
【约束】权重只能通过接口参数传，不许改 config/scenarios/*.toml 的默认值；
        三个权重之和归一化到 1，显示两位小数
【验收】① 拖到"省钱 1.0"和"省时 1.0"两次截图，行程必须不同（否则就是没生效）
        ② 快速连拖 10 次，最多只发出 1 次请求（在 network 面板里数）
【禁区】不许把权重写进前端常量；不许删掉已有的"一句话调整"入口
```
**反模式**：它会加个 `setInterval` 轮询——用防抖，别轮询。

### T27 · 两套方案并排对比

```text
把"算法对比"从页签改成一张并排视图。

【目标】上下两栏（或左右两栏），两根轴用同一时间刻度对齐，同一时间段的块左右对齐；
      标出差异：多出的站、省下的钱、多走的分钟；最优一套用朱红细边框标出
【数据】复用现有 /api/compare，不许新写接口
【约束】两栏时间刻度必须共用同一个 PPM 与同一个 T0，否则对比是假的
【验收】截图一张；同一小时的刻度线在两个栏里必须水平对齐（用标尺量或断言 offsetTop 相等）
【禁区】不许用柱状图代替轴 —— 柱状图看不出"时间冲突"，那正是要展示的东西
```
**反模式**：它会给你两张各自缩放到"刚好填满"的轴，看着整齐，实际上两栏时间不再可比。

### T28 · 打印这张纸 / 导出单文件 HTML

```text
加"导出这张纸"。

【目标】① 浏览器打印（Ctrl+P）时只输出轴 + 旁注 + 指标，隐藏输入条与按钮
        ② 另给一个"下载 HTML"：把当前行程数据内联到一个自包含 HTML 里，断网双击可看
【约束】打印样式用 @media print；导出文件不许引用任何外部资源（无 CDN、无字体文件）；
        文件 < 200KB
【验收】① 打印预览截图 ② 导出的 HTML 断网打开截图 ③ 文件大小用 dir 命令证明 < 200KB
【禁区】不许用截图代替（那是图片，搜不了、选不了）
```
**反模式**：它会用 html2canvas 截图导出——那就成了一张图，评审问"这段能不能搜"就露馅。

### T29 · 手机竖屏

```text
只加 ≤480px 断点。

【目标】375×812 下：轴保持纵向、宽度收窄；旁注折叠为"点站块 → 下方展开"；
      滑杆变整宽；按钮触控区 ≥44px；横向无滚动
【约束】不许为手机另写一套 HTML；不许隐藏"没排进去的"区块（那是卖点）
【验收】① document.scrollWidth <= 375 ② 截图 375×812 两张（折叠前/展开后）
        ③ _render_check.js 增加这条视口断言并跑绿
【禁区】不许用 `transform: scale()` 把小屏"缩小显示"
```
**反模式**：它会 scale 缩放，字变小但布局没变——那等于没适配。

### T30 · 文案去 AI 味

**用在哪**：视觉定稿之后。**界面的一半是字。**
```text
只改界面上的静态文案与解说模板，不改逻辑。

【目标】按下面这张替换表改写全部界面文字，语气统一为"同事说话"：
  优化 / 智能化 / 一站式 / 赋能 / 打造 / 全面提升 → 删掉，直接说做了什么
  "根据您的偏好为您推荐" → "命中兴趣：图书馆、自习"
  "抱歉，未能找到合适方案" → "4 个点都排不下，因为预算只剩 12 元"
  "正在为您智能计算中" → "算一下，约 0.2 秒"
【约束】每句必须能回答"谁、做了什么、多少"；不许出现感叹号；不许出现"我们"
【验收】把界面上所有文案导出成一个列表给我，逐条对照替换表打勾
【禁区】不许改动 JSON 字段名（文案只在渲染层改）
```
**反模式**：它会把文案改得更"亲切"，加一堆语气词——你要的是短和准，不是热情。

### T31 · 收口、冻结、留证据

```text
【目标】① 视觉冻结：此后只修 bug，不加功能 ② 留证据：design/shots/ 存 6 张标准截图
      ③ 打 tag：v1.2-ui
【六张标准截图】首页空态 / 一条单日行程 / 多日行程 / 有跳过项 / 两套并排 / 375px
【验收】① 294 个测试全绿 ② _render_check.js 全绿 ③ tools/make_demo_outputs --verify 全部一致
        ④ 首页 HTML 文件大小 < 60KB（现在是 45KB，不许翻倍）
【禁区】不许在冻结后"顺手"改配色或字号 —— 一律进下一轮
```

### 4.1 每周五 15 分钟自检（四条，红一条就停）

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -t .
.venv\Scripts\python.exe -m tools.make_demo_outputs --verify
node _render_check.js
dir web\index.html        # 体积没暴涨
```

### 4.2 你会遇到的最大的三个坑（提前说）

1. **AI 会想把四个页签都留下来。** 你的立场：**一个页面只能有一个主视图**。想留的全部折叠。
2. **真实比例会让页面出现大片空白**（比如 90 分钟的图书馆块很高）。不要用 min-height 去"填平"——用块内的 15 分钟横线让高度变得可数（样张里就是这么做的）。
3. **你会想加动效。** 四周内不加。动效是最后 10% 的分数，而你现在连前 90% 都还没冻结。

## 六、和开题承诺的差异，怎么跟老师一句话说清

开题 PPT 里"城市插件化 / 个性化推荐"占了两个里程碑，这四周不做。说法：

> "插件机制的数据结构（`data/cities/registry.toml` + `tools/new_city.py`）已经在仓库里，按需加载随时能加；
> 这一阶段我们先把'看一份行程'这件事做透——**把可计算、可解释、可核查变成三个看得见的东西**，
> 因为评委会记得住界面，记不住任务清单。"

**别说"砍了"**，要说"顺序变了，机制已就绪"。这两句话的事实是一样的，但一句像失控，一句像取舍。
