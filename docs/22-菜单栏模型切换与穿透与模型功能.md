## 一、菜单栏已经加到真实页面了（不是原型）

打开 <http://127.0.0.1:8000/>，最上面那条黑色/白色横条就是：

```
AI 出行 │ 模型 [自动（按难度挑）▾]  自动路由：按难度挑 │ 主题 [浅][暗][纸] │ [地图][模型对比][?]
```

### 1.1 模型：自动 / 手动，两种都在

| 模式 | 怎么选 | 行为 |
|---|---|---|
| **自动**（默认） | 下拉留空 | 按 `LLM_ROUTER=llm` 的规则挑：简单句走 `GLM-4.6`，常规走 `DeepSeek-V4-Flash`，复杂约束走 `Qwen3-Next-80B-Thinking` |
| **手动** | 下拉选具体模型 | **整次请求锁定这一个**，绕过路由。结果更可预期，适合答辩时"我要每次都一样" |

- 选项来自 `GET /api/options` 的 `models`（去重后带角色标签，标 `· 主力` 的是默认那个）；
- 选择存本地（`localStorage`），下次打开还在；
- 生成完行程后，菜单栏那行字会变成 **「本次：模型名（角色）」** —— 自动路由时，这是唯一能看见"到底用了谁"的地方。
- 后端实现：`usecases.llm_client(model)` 手动时**浅拷贝一份**改 `model`，不动全局单例（否则两个人同时用会互相覆盖）。

### 1.2 主题：三套，只换配色不动结构

浅 / 暗 / 纸 —— 全部通过改 CSS 变量实现（`html[data-theme=...]`），所以：

- 切主题**不会**动布局、不动 DOM，不会"换皮就错位"；
- 记在本地，下次还是上次那套；
- 想加第四套：只要再写一组 12 个变量，**一行结构都不用改**。

### 1.3 三个快捷按钮

| 按钮 | 作用 |
|---|---|
| **地图** | 直接打开地图页签并渲染（= 原来的"地图"页签，少点一次） |
| **模型对比** | 同一句话跑两遍（规则 vs 模型），出四行对照表 |
| **?** | 弹出菜单说明 |

## 二、cpolar 穿透：你这台机器的具体步骤

前提（已具备，不用再注册）：`E:\cpolar\cpolar.exe` 已装、authtoken 已配、后台那条隧道的**目标端口是 8080**。

### 第 1 步：确认 cpolar 在线

```powershell
cd E:\cpolar
.\cpolar.exe status
```

- 显示 `Active` / `online` → 直接进第 3 步；
- 显示未启动 → `.\cpolar.exe service start`（装过服务）或 `.\cpolar.exe start`（前台跑）。

> 也可以在浏览器开 <http://127.0.0.1:9200> —— cpolar 的本地管理界面，能直接看到**当前公网地址**。

### 第 2 步：确认隧道指向 8080

在 9200 管理界面看那条隧道的 `Local` 字段是不是 `http://localhost:8080`。
不是 8080 的话，把 `分享给他人.bat` 里的 `set PORT=` 改成隧道那个端口，两边必须一致。

### 第 3 步：把服务起在 8080（必须用这个脚本，不是 8000 那个）

双击 **`分享给他人.bat`**。窗口里会出现：

```
正在以"可分享"方式启动（端口 8080）
口令：trip-8261
```

**这个窗口不能关。**

### 第 4 步：拿公网地址

- 有 9200 面板：直接看 `https://xxxx.r8.cpolar.cn`；
- 没有面板：双击 **`3-开穿透.bat`**，它会跑 `tools.tunnel` 并把地址打印出来。

### 第 5 步：先自检，再发人

```powershell
cd D:\projects\ai-trip-planner
.venv\Scripts\python.exe -m tools.share_link https://xxxx.r8.cpolar.cn --port 8080 --check
```

看到 `公网 … [OK] HTTP 200` 才发。发这条：

```
https://xxxx.r8.cpolar.cn/?code=trip-8261
```

### 第 6 步（可选）想要固定地址

免费隧道**每次重启域名就变**。固定地址要么 cpolar 付费版（保留二级域名），要么换 Cloudflare Tunnel（自有域名，约 10 元/年）。

### 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| 公网 502 | 隧道指 8080，服务起在 8000 | 用 `分享给他人.bat`，别用 `1-启动网站.bat` |
| 页面能开、接口 401 | 链接没带 `?code=` | 用完整链接；弹框时输口令 |
| 昨天能开今天 502 | cpolar 掉线 / 域名变了 | `.\cpolar.exe status` 看一眼，重拿地址 |
| 免费版提示隧道数超限 | 免费只有 1 条 | 关掉多余隧道 |

## 三、让大模型"看得见"的五个功能（按"一眼看出"排序）

判断标准只有一条：**关掉模型，这个功能就没了**。做不到这点的，都不算"用上了模型"。

### ★ 1. 行程体检官（半天，最容易看出效果）

点一下「体检」，把当前行程交给模型，让它以"带队老师"的口吻挑毛病：

> 「第 2 站到第 3 站之间要走 18 分钟，但你只留了 10 分钟 —— 会迟到。
> 另外 11:30 那站是食堂，人最多的时候，建议提前到 11:10。」

- **为什么非模型不可**：规则能算出"18>10"，但说不出"食堂 11:30 人最多"这种常识；
- 成本：1 次调用；输出 3–5 条，带严重度。

### ★ 2. 反向规划（1 天，答"我几点必须走"）

输入"我 16:00 必须离校"，系统**倒着排**：先把最后一站定在 15:10，往前推。
这是访客最真实的约束（赶高铁），而现在的正排算法只会"排满了算总时长"。

### ★ 3. 预算谈判（1 天，已有设计未实现）

超支时不报错，给三个方案让用户点：砍一站 / 换更便宜的食堂 / 缩短停留。
**模型只出选项，Python 执行** —— 这条界线本身就是卖点。

### 4. 两种口吻的同一份行程（2 小时）

同一个结果，给"同行同学"和"给家长看"两版文字：前者短、口语；后者多一句"安全提醒"。
实现只是 prompt 里加一个 `audience` 参数，**不增加调用次数**。

### 5. 校园讲解词（半天）

每个站生成 60–100 字的"到了该看什么"，可直接当录音稿（后续接 TTS 就是语音导览）。
校史馆/伯川图书馆这类有故事的站点效果最好。

## 四、我建议的先后顺序

| 顺序 | 做什么 | 理由 |
|---|---|---|
| 1 | **行程体检官** | 半天就能上，且"关掉模型就没了"最明显，答辩现场点一下就有反馈 |
| 2 | **预算谈判** | 交互感最强，且呼应"模型出选项、代码算数字"的主张 |
| 3 | 反向规划 | 真正解决访客"赶时间"的痛点，但要改规划器 |
| 4 | 口吻两版 / 讲解词 | 锦上添花，可选 |

```text
你是带队老师。下面是学生排好的一天行程（含每站到达/离开、停留、花费、步行分钟）。

严重度（高/中/低）、问题、证据（引用具体数字）、一句话建议。

```

## 五、四个创新点已全部实现（2026-11-03 22:10）

### 5.1 界面在哪

生成行程后，结果区顶部会出现一张 **「智能工具」** 卡（在行程表上方）：

```
智能工具   数字本地算，模型只写话
[讲解词]  [同学口吻]  [家长口吻]
[看省钱方案（超支时用）]
```

左侧输入区新增 **「最晚离校（可选）」** 时间框 —— 填了它，`/api/plan` 会多返回一段 `reverse` 提示，
显示在「智能工具」卡的最上方。

### 5.2 契约

```jsonc
// ① 反向规划：随 /api/plan 一起返回
POST /api/plan {"query":"…","must_leave":"16:00"}
→ {"plan":…, "reverse":{"ok":true,"must_leave":"16:00","arrive_by":"10:24",
                        "span_min":336,"stops":4,"cut":0,
                        "note":"要 16:00 前离校，最晚 10:24 到校（全程约 336 分钟）"}}

// ②~④ 共用一个端点
POST /api/extras {"action":"negotiate","plan":{…}}
POST /api/extras {"action":"audience","audience":"peer|parent","plan":{…}}
POST /api/extras {"action":"spiel","plan":{…}}
```

### 5.3 实测输出（真跑，不是示意）

**反向规划**（`must_leave=16:00`）：
> 要 16:00 前离校，最晚 **10:24 到校**（全程约 336 分钟）

**省钱方案**（花费 24 元，3 个可点方案，数字现算）：
| 方案 | 省 | 一句话 |
|---|---|---|
| 少去一站 | 12 元 | 少去一站，省 12 块 |
| 切省钱档 | 6 元 | 切省钱档，省 6 块 |
| 放慢节奏 | 0 元 | 放慢节奏，不省钱（但时间松） |

点「用这个」→ 前端把对应 `overrides` 合并进原请求**重新规划**，所以数字仍然是真的算出来的。

**同学口吻**：
> 早上 7 点半从伯川图书馆出发，逛了 4 个点，中间停了 320 分钟，路上才 15 分钟，
> 最后 13 点 06 到第二食堂。总共花了 24 块，挺顺的……

**讲解词**（每站 60–100 字，带保守措辞）：
> 这里是伯川图书馆，校园里主要的自习和藏书空间之一。馆内设有多个阅览区，适合安静学习。
> 如果来得早，可以在门口稍候，开放后建议先逛一层大厅，再选个靠窗位置。
> 建议停留约两小时，**以现场开放……**

### 5.4 三条要写进报告的限制

| 限制 | 说明 |
|---|---|
| **反向规划只给"最晚到校"，不重排** | 现在是用实际跨度平移算出来的；真正倒排需要引擎支持"从 end_time 反向填轴"，还没做 |
| **"切省钱档省 25%" 是估值** | 真正的省钱额要重排完才知道；现在的数字是保守估计，点下去以后以新行程的实际花费为准 |
| **口吻偶尔太随意** | 同学版出现过"就是食堂有点多哈哈"。要去掉就收紧 prompt（加一句"不要语气词"） |

### 5.5 一处工程细节（踩过）

`_spiel_template` 里 `("…%s…" % (a, b).replace(...))` 会先对 **元组** 调 `.replace` 而报
`'tuple' object has no attribute 'replace'` —— 必须先把 `%` 的结果赋给变量，再 `.replace`。

### 6.2 三套主题：换的是版式，不只是颜色

| 维度 | 浅色（默认） | 纸质 | 暗夜（仪表盘） |
|---|---|---|---|
| 标题字体 | 系统无衬线 | **宋体/思源宋体**，字距 1.5px | **等宽** |
| 卡片 | 白底 + 圆角 10px + 细边 | **透明底 + 无圆角 + 仅下框线** | 深色渐变 + 4px 圆角 + 亮边 |
| 章节标记 | 无 | **`§` 前缀**（报纸分节感） | 无 |
| 指标网格 | 6 列方块 | **3 列，左侧竖线 + 衬线数字** | **3 列，深底 + 左侧亮条 + 等宽数字** |
| 按钮 | 实心蓝 + 圆角 7px | **透明底 + 描边 + 方角 + 加粗** | 深底描边 + 3px 小方角 |
| 页签 | 白底胶囊 | **下划线式**（无底色） | 深底块 + 选中实心 |
| 背景 | 纯色 | **横线稿纸** | **32px 网格** |
| 栏宽 | 340 / 1fr | 300 / 1fr（留白更大） | 320 / 1fr（更紧凑） |

地址栏加 **`?theme=paper` / `?theme=dark` / `?theme=light`** 可直接指定主题——
截图、演示、发链接给别人都方便，不用点按钮。

> 判断"是不是只换了颜色"：把三张截图转灰度。若版式结构仍能分辨，就是改了排版；
> 若只剩明暗差，那就是换皮。这三套在灰度下依然可区分。

### 6.3 现在一共六套（2026-11-03 23:10 追加三套）

| key | 名字 | 一句话认出来 |
|---|---|---|
| `light` | 浅色 | 默认：白卡、蓝按钮、六格指标 |
| `dark` | 暗夜仪表盘 | 等宽字体 + 32px 网格 + 左侧亮条指标 |
| `paper` | 纸质杂志 | 宋体标题 + `§` 分节 + 只有下框线 + 横线稿纸 |
| `naiwa` | **奶蛙** | 奶绿波点底 + 20px 大圆角白卡 + 绿色立体按钮（按下去会下沉） |
| `pixel` | **像素复古** | 等宽 + 硬边框 + 4px 硬阴影（无模糊）+ 扫描线 + `> ` 前缀 |
| `cyber` | **赛博霓虹** | 切角卡片 + 青紫渐变标题 + 荧光描边 + `// ` 前缀 |

菜单栏「主题」是一个下拉（六项），选择存 `localStorage`；也可以用
`?theme=naiwa|pixel|cyber` 直接指定。

**三套新主题的记忆点各不相同**：

- **奶蛙**：靠**圆角 + 立体**取胜。按钮 `box-shadow: 0 4px 0` 是天生"厚度"，
  `:active` 时 `translateY(2px)` 把厚度压掉 —— 点下去有物理感。指标卡用虚线边框，像贴纸。
- **像素**：靠**硬阴影 + 等宽**取胜。`box-shadow: 6px 6px 0`（**0 模糊**）是像素风的灵魂，
  一加模糊立刻变"现代卡片"；背景叠 `repeating-linear-gradient` 做 CRT 扫描线。
- **赛博**：靠**切角 + 发光**取胜。`clip-path: polygon(...)` 切掉两个对角，
  比圆角更有"设备面板"味；标题用 `background-clip:text` 做青→品红渐变。

**扩展成本**：每套只需一段 `html[data-theme="x"]{...}` —— 先定义 12 个颜色变量，
再按需覆盖 6~8 条结构规则（卡片圆角/阴影、按钮形状、指标列数、字体、背景纹理）。
**加第七套不碰任何已有代码**，这是"变量 + 结构覆盖"相对"改样式表"的直接好处。
