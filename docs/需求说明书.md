## 一、待确认的阻塞级问题（问助教）

| # | 问题 | 影响 |
|---|---|---|
| Q1 | 提交物是「代码仓库 + 报告 PDF」还是「可运行程序 + 演示视频」？ | 决定文档 vs 代码 vs 演示的投入配比 |
| Q2 | 评分 rubric 的维度与权重？ | 决定做"炫"还是做"稳" |
| Q3 | 截止日期 + 有没有中期检查？ | 中期检查日 = 硬里程碑 |
| Q4 | 允许多大程度使用 AI 生成代码？是否要求标注？ | 要求标注则从第一天就在注释和报告里留痕（反而是加分项） |
| Q5 | 能否联网 / 能否调第三方 API（地图、天气、大模型）？ | 若需 API Key，实名+配额要 1–2 天，必须第一天启动 |
| Q6 | 两人同分，还是要交个人贡献说明？ | 要区分则"谁做了什么"的留痕是刚需 |

## 二、待确认的设计级问题

| # | 问题 | 建议默认值 |
|---|---|---|
| Q7 | 目标用户与场景 | 越窄越好做，锁定一个极具体场景 |
| Q8 | 输入是自然语言还是表单 | 自然语言为主 + 表单兜底 |
| Q9 | 数据来源 | 手工整理 50 个高质量 POI 胜过爬 5000 条垃圾 |
| Q10 | 要不要真实路径/时间计算 | 没有 API 就用「距离 × 系数 + 校正表」，数学学院做误差分析反而是亮点 |
| Q11 | 硬约束有哪些 | 开放时间、预算、体力/步数、闭馆日、天气、用餐时间窗 |
| Q12 | 要不要多目标优化 | 至少做「省钱 / 均衡 / 尽兴」三档权重 |
| Q13 | 要不要对比实验 | **强烈建议做**，成本一个下午，最容易拿分 |
| Q18 | 队友水平如何 | 决定角色分配（见 `docs/分工与所有权.md`） |
