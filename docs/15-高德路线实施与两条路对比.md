# 15 · 高德路线：怎么做，以及它和"拿校方授权"到底差在哪

> 版本 v1.1 ／ 2026-11-02 起草，2026-11-03 接通并实跑验证 ／ 回答两个问题：
> **① 大连理工能不能完全用"高德 POI + 高德底图"做出来、怎么做；② 高德路线和授权路线差在哪。**
> 结论先说：**能，而且已经接通跑通了（见文末"实跑记录"）；授权只是锦上添花，不是前置条件。**

---

## 一、先看清楚：你手里 46 个点本来就是高德的

| 你现在有的 | 来源 | 说明 |
|---|---|---|
| 46 个 POI（坐标、开放时间、费用） | 高德 POI 搜索 + 手工核实 | 坐标是 **GCJ-02**，交给高德 JS API **不用做任何转换** |
| 145 条步行耗时 | `tools/amap_matrix.py` 调高德步行路径规划 | 抓一次写进 CSV，**运行时零联网** |
| 地图渲染 | `web/index.html` 已有 `AMAP_JS_KEY` 开关 + 失败回退 SVG | 代码就绪，**只差 Key 没填** |

所以"高德路线"对你不是另起炉灶，而是**把最后一块（底图）接上**。缺的东西一共三件：

1. 一个 **Web端(JS API)** Key（免费，实名后即时）；
2. 一个**安全密钥**（2021-12-02 之后新建的 Key 必须有，否则报 `INVALID_USER_SCODE`）；
3. 前端把这两样塞进 SDK 初始化（约 5 行）。

---

## 二、具体怎么做：五步，半小时内能出图

### 步骤 1 · 申请（10 分钟）

高德开放平台控制台 → 应用管理 → 创建新应用 → 添加 Key：

| 项目 | 选什么 | 为什么 |
|---|---|---|
| 服务平台 | **Web端(JS API)** | 前端显示地图用这个 |
| 域名白名单 | 先填 `localhost`；上线后加你的域名 | 不填白名单会被拒 |
| 安全密钥（jscode） | 与 Key 同时生成，**两串都要抄下来** | 2.0 版 SDK 强制校验 |

> 注意：你 `.env` 里的 `MAP_API_KEY` 是**另一个 Key**（服务平台要选「Web服务」，抓 POI/矩阵用）。
> **两个 Key 不是一回事**，填错位置会 401 或 `INVALID_USER_KEY`。

### 步骤 2 · 填配置（3 行）

```dotenv
# 项目根 .env
AMAP_JS_KEY=你刚才申请的 JS API Key
AMAP_SECURITY_CODE=同一页面上的安全密钥
```

`service/usecases.py` 里那一行要顺手加个字段（现在只有 `js_key`）：

```python
"map": {"js_key": env("AMAP_JS_KEY", ""),
        "security_code": env("AMAP_SECURITY_CODE", "")},
```

### 步骤 3 · 前端初始化（关键：先设安全密钥，再加载 SDK）

现在 `web/index.html` 的 `loadAmapSdk()` 是这样：

```js
s.src = 'https://webapi.amap.com/maps?v=2.0&key=' + encodeURIComponent(JS_KEY);
```

**必须改成**（顺序不能反）：

```js
window._AMapSecurityConfig = { securityJsCode: SEC_CODE };   // ← 必须在 SDK 之前
s.src = 'https://webapi.amap.com/maps?v=2.0&key=' + encodeURIComponent(JS_KEY);
```

> ⚠️ **这是最容易卡住的一步**：Key 没错、白名单也对，页面却一片空白、控制台报
> `INVALID_USER_SCODE`，九成是漏了这一行。文档里没写、报错也不直白。

### 步骤 4 · 选底图（校园场景推荐"卫星 + 路网"）

高德给三种，校园里观感差别很大：

| 底图 | 代码 | 校园里的效果 | 适合 |
|---|---|---|---|
| 矢量（默认） | `new AMap.TileLayer()` | 只有路和色块，**看不到操场、湖、楼顶** | 通用导航 |
| **卫星** | `new AMap.TileLayer.Satellite()` | **能看到跑道、绿化、建筑屋顶**，一眼认出"这是我们学校" | ★ 校园首选 |
| 卫星 + 路网 | 上面两个叠加 `new AMap.TileLayer.RoadNet()` | 影像 + 道路名，最好看也最费一点性能 | ★ 答辩演示 |
| 3D 楼块 | `new AMap.Buildings()`（`zoom ≥ 17` 才显示） | 有体积感的楼块，但没有楼名 | 加分项 |

### 步骤 5 · 叠加四层（这才是"你的地图"）

| 层 | 怎么画 | 数据从哪来 |
|---|---|---|
| 站点 | `AMap.Marker` + 自定义 HTML（带序号、站名） | 你的 `ItineraryItem` |
| 路线 | `AMap.Polyline`（**直线连，不调路径规划**） | 顺序来自规划结果 |
| 每段耗时 | Polyline 上挂 `LabelMarker` 或自绘 div | `travel_matrix.csv` 的实测值 |
| 校区边界 | `AMap.Polygon`，用编辑器手点一圈导出 | 自己描，存 `campus.json` |

> **为什么路线用直线、不调高德的路径规划**：一调就出现"你画的线"和"高德算的线"两套东西，
> 而且每次调用都吃配额、结果还可能变。你的卖点是**可复现**，直线 + 实测分钟数就够，
> 反正在校园里也都是一两百米的直线距离。

## 三、配额这件事：你其实已经绕过去了

| 调用 | 什么时候发生 | 吃配额吗 |
|---|---|---|
| POI 搜索、步行矩阵 | **只在你手动跑工具时**，抓一次写进 CSV | 吃一次，之后再也不吃 |
| 运行时 `plan()` | 读本地 CSV 计算 | **不吃**（零联网） |
| 前端显示底图 | 用户打开页面 | 吃 JS API 的日额度（个人开发者有免费日额度，以控制台为准） |

**这就是你现在这套设计最值钱的地方**：把"贵且会变"的调用挪到离线，把"便宜且稳定"的调用留在运行时。
答辩机断网也能演示，额度也不会被刷爆。

## 四、高德路线 vs 授权路线：十项对比

| 维度 | 高德路线 | 校方授权路线 |
|---|---|---|
| **拿到什么** | POI 点 + 矢量/卫星底图 | 校方**测绘级**瓦片：楼栋轮廓、屋顶、内部道路、绿化 |
| **坐标精度** | POI 约 10 m 级 | 测绘级（米级），但**你的瓶颈其实是配准误差 3–5 px** |
| **语义精度** | 只有"点"，没有"这栋楼长什么样" | 能看清**哪栋是伯川图书馆**、哪条是小路 |
| 合规 | ✅ 公开授权，标注"© 高德地图"即可 | ✅ 但**仅限授权范围**，一校一份，不可外溢 |
| 成本 | 0 元 + 30 分钟 | 0 元 + 一封邮件 + 1–5 天等待 + 四条承诺 |
| 覆盖率 | **任何学校都能做** | 取决于该校有没有平台、愿不愿批 |
| 稳定性 | 商业服务，有 SLA | 校内老服务器（nginx 1.10.2），**并发差，别刷** |
| 观感 | "像地图 App"——好看，但**辨识度是高德的** | "独一份"——别人做不出来 |
| 扩展性 | 无限 | 每校重走一遍流程 |
| 答辩风险 | 几乎没有（来源正当、随时可复现） | 要能说清"谁批的、范围多大、什么时候删" |

### 一句话说清差别

> **高德回答"位置对不对"，校方图回答"这是哪栋楼"。**
> 前者是"能不能用"，后者是"好不好看、独不独特"。

而且要诚实：**在"排行程"这件事上，两者对结果的影响几乎为零**。
你的规划用的是坐标和步行分钟数，这两样高德都给得比校方图更规范（GCJ-02、有 API）；
校方图真正多的价值，是**地图上的可读性和辨识度**，不是计算精度。

## 五、我的建议：分工，不要二选一

| 用途 | 用哪个 | 理由 |
|---|---|---|
| 规划与计算（选点、排程、校验、评测） | **永远用高德 POI + 实测矩阵** | 可复现、零联网、可扩展、合规 |
| 地图默认显示 | **高德（卫星 + 路网）** | 立刻可用，任何学校都能上 |
| 地图"精细模式"（可选） | 校方瓦片，**授权到手才开** | 作为彩蛋，不作为依赖 |
| 没授权 / 没网 / Key 失效 | 离线 SVG + 配准图 | 已有兜底，保持 |

**这个分工的好处**：授权从"前置条件"降级成"加分项"。也就是说——

> **其他学校授权拿不到，完全不影响你做。** 全部走高德路线，两小时一所，
> 精度等级标 L2（POI 真实 + 耗时实测），地图上写"底图：高德"。**这已经是能答辩的状态了。**

## 八、实跑记录（2026-11-03 00:40–00:48）

**已接通，四个证据：**

| # | 验证项 | 结果 |
|---|---|---|
| 1 | Key + 安全密钥在 SDK 层是否有效 | ✅ 独立自检页加载成功，**卫星 + 路网瓦片渲染完成**（能看到操场跑道、凌水河、楼顶），无 `INVALID_USER_SCODE` |
| 2 | 后端是否把两把配置下发给前端 | ✅ `GET /api/options` → `map.js_key` 32 位、`map.security_code` 32 位 |
| 3 | 真页面能否出图 | ✅ 首页点「生成行程」→ 切「地图」页签，高德 SDK 初始化成功、站点 Marker 与虚线路径正常绘制 |
| 4 | 失败是否优雅降级 | ✅ 故意让 SDK 加载失败：标题变成「路线图（离线绘制）· 高德底图不可用：SDK 加载失败」，**SVG 兜底照常显示，不白屏** |

**改了什么（4 处，都在 12 行以内）：**

| 文件 | 改动 |
|---|---|
| `.env` | 新增 `AMAP_JS_KEY` / `AMAP_SECURITY_CODE`（`.env` 已被 gitignore，不进仓库） |
| `.env.example` | 补两个变量的说明（含"2021-12 后新建 Key 必配安全密钥"这条坑） |
| `service/usecases.py` | `map` 字典加 `security_code` |
| `web/index.html` | ① 新增 `SEC_CODE` 变量与读取；② `loadAmapSdk()` 在插 `<script>` 前设 `window._AMapSecurityConfig`；③ 默认叠加卫星+路网（`try/catch`，失败保持矢量）；④ SDK 超时 8s → **12s** |

**顺带查出的两个真问题：**

1. **SDK 超时 8 秒偏紧**。和当年 `LLM_TIMEOUT` 8s→30s 是同一类事故：校园网 + 首次加载 SDK（约 1MB）
   容易踩线，一旦超时就退回 SVG，答辩时看着像"地图坏了"。已改 12s。
2. **46 个点的坐标是 `seed`，不是高德实测**。`pois.csv` 的 `source` 列全是 `seed`、`source_date` 留空，
   页面上自己也报「待核实 2 项」。也就是说：**底图现在是准的，点还只是近似位置**。
   要把数据从 L1 提到 L2，得跑一次坐标校正（把每个 seed 点吸附到高德最近的同名 POI，人眼抽检 10 个）。
   这是下一步最值得做的一件事——**它比换底图更能提升"行程对不对"**。
