# 24 · 城市约会模式设计（v1.5）

> 状态：已实现（引擎 / 服务 / 接口 / 网页 / LLM 五层全部落地，320 个测试全绿）
> 关联：`docs/接口契约.md`（v1.5 修订）、`config/scenarios/date.toml`、`docs/14-多校区扩展方案.md`（数据路由修复）

## 一、这个模式解决什么问题

用户原话（需求来源）：

> "在大学游览之外开一个另外的分支，在某个城市中的约会规划……可以选定一个约会的中心，
> 辐射周边好玩的地方开始规划，可以输入起始时间……到目的地要去哪个餐厅，
> 电影开场时间等约束，越详细越好。可以进入网页出现校内游览模式，约会模式等"

约会和"逛校园"的根本区别在于**硬时刻**：电影 14:30 开场不等人、餐厅订座 18:00 不能迟。
通用贪心算法把"想去哪"排出来就完了，但约会需要把"必须几点在哪"钉死，
剩下的时间围绕锚点填充。这就是 date 策略的全部设计动机。

## 二、契约：只增不改（v1.5）

`PlanRequest` 末尾追加两个字段（都有默认值，旧 JSON 完全不受影响）：

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `zone` | `str = ""` | 商圈/分区（如"西安路"）。非空时候选池过滤 `poi.zone == zone`；筛不出**放开过滤**而不是返回空行程 |
| `anchors` | `list[dict] = []` | 锚点/预订约束：`{"poi": 名称或poi_id, "time": "HH:MM", "duration_min": 120, "label": "电影开场"}` |

配套改动：

- `POI` 末尾追加 `zone: str = ""`（约会点位表用，其他表为空不影响）
- `schemas/itinerary.schema.json` 同步（AC-51 有机器测试锁住）
- 违规码新增 `ANCHOR_MISS`：晚到 / 认不出 / 时刻非法**只进 warnings，绝不抛异常**

## 三、date 策略（`engine/strategies.py::date_plan`）

1. 锚点解析 `_resolve_anchors`：poi 认不出 / 时刻非法的条目跳过（留给校验层告警），按时刻升序。
2. **切段**：锚点把一天切成若干段；`arrive` 钉死在锚点时刻、`leave = 时刻 + duration`。
3. **段内填充** `fill_until(deadline, back_to)`：贪心往段里塞候选，硬条件是
   `玩完的在途时间 + 下一锚点的赶路时间 <= deadline` —— 即"还要来得及赶回**当前**锚点"
   （注意是回到当前锚点再出发，不是直奔下一个锚点；这里的坑见测试
   `test_fill_ends_before_next_anchor`）。
4. 末段自由填充到 `day_end`；无锚点时退化为 `_greedy_one_day + _fill_day`（不返回空行程）。
5. 只产出一天（约会是单日事件）。

### 迟到只告警不拒绝

出发太晚 + 锚点太早时，行程照出，`ANCHOR_MISS` 告警写明"最多可能晚到 N 分钟"。
原因：拒绝输出等于让整个功能在真实使用里变成"动不动就报错"，
而告警 + 让用户自己改时间，与本项目"违规进 warnings"的哲学一致。

### 校验器口径

`validate_anchors` 的迟到判定**直接读行程项已存的 `it.transport.minutes`**
（即策略排程用的同一条边），不重算交通边 —— 消除"矩阵边 vs 直线估算"1~2 分钟
口径差导致的假告警。

## 四、数据

- `data/cities/dalian/pois_date.csv`：29 点、19 列（含 `zone`）。
  两个商圈：**西安路**（DL201–DL215）与**星海**（DL220–DL233）。
- 标签词汇隔离：约会 POI 的餐饮用 tag `正餐` 而不是 `餐饮` ——
  否则会污染 daily 场景"吃饭"→`["食堂","餐饮"]` 的 alias 匹配，把西安路的
  饭馆排进校园日常行程。
- `data/cities/dalian/showtimes.json`：三家影院的**演示场次**
  （`_note` 已声明；对接真实票务只换此文件，引擎与前端零改动）。
- **场景级数据路由修复**（`data/loader.py::_poi_file_for`）：优先级改为
  「场景显式点位表（≠`pois.csv` 且存在）> 城市注册表 > 内置默认」。
  修复前 visit.toml 的 `pois_campus.csv` 一直被注册表盖掉，是死配置；
  修复后 date 得到独立点位表，visit 的文档意图被顺带恢复，daily/demo 零影响。

## 五、服务与接口

| 端点 | 作用 |
| --- | --- |
| `GET /api/date/info` | 商圈列表、影院与场次、商圈中心、餐厅候选（面板初始数据；`source=demo` 原样透传） |
| `POST /api/date/locate` | `{"lat","lon"}` → 按各商圈 POI 质心的直线距离找最近商圈（离线可复现，不调外部 API） |
| `POST /api/date/brief` | 一站式：排程 + 简报。body 里 `movie`/`dinner` 由服务端拼成锚点，也可 `{"anchors": [...]}` 直传 |

关键实现约定：

- `service/usecases.py::sanitize_anchors` **只洗形状、不做语义裁决**——
  时间写错、地点认不出都原样传给引擎，由 `validate_anchors` 统一告警。
  这样「直接构造 PlanRequest」和「走接口」两条路径行为完全相同。
- `service/date_mode.py::anchors_from_body` 的时长不问前端：按 POI 表
  `stay_min` 取（电影 120、晚餐 60~90）。
- `POST /api/date/brief` 的坑：`_run_plan` 内部只认 `body["overrides"]`，
  面板拼出的约束**必须合并回 body**，否则全部被静默丢弃（冒烟测试抓出来的真 bug）。

## 六、LLM 简报（`llm/date_brief.py`）

与 `llm/guide.py` 完全同构的三层：

1. **事实卡**：行程每站（arrive/leave/stay/cost/在途）+ 锚点原样列表；
2. **模型只措辞**：SYSTEM 里硬规则"只能引用给定事实，锚点时刻不许改动"；
3. **`_fallback()` 确定性模板**：无 Key / 模型失败时同样输入同样输出。

输出键（headline/before/timeline/per_stop/tips/verify）与访客简报对齐 ——
前端一套渲染逻辑两种模式共用。

## 七、网页（`web/index.html`）

- 顶部三模式页签：**校内游览（daily）/ 访客参观（visit）/ 城市约会（date）**，
  与场景下拉双向联动（点页签 = 切场景 + 同步该场景默认算法）。
- `#datePanel`：商圈下拉、开始时间、影院+场次（随商圈联动过滤）、
  晚餐订座+时间、出发地、「📍 我在这里」定位按钮。
- 约会模式走 `POST /api/date/brief`，简报卡片（`briefCard`）渲染在行程上方。
- 前端自检 `node _render_check.js` 增加 [4] 组断言：
  简报卡片渲染、headline、电影 14:30 钉死在行程表。
  （自检脚本的 DOM 桩补齐了 `documentElement/style/setAttribute/remove/insertBefore` ——
  主题与智能工具条代码比桩新，桩一直没跟上。）

## 九、已知边界

- 场次为演示数据（答辩口径）。
- `locate` 用商圈质心直线距离，不是步行导航距离 —— 够用（二选一商圈），不做导航。
- date 场景只排一天；跨天约会（订酒店）不在本期范围。

## 十一、v1.6.3 独立化：城市口径 + 筛选细化 + 一句话优先

用户反馈三件事，逐条落地：

1. **约会模式的地点以「城市」为准，不再挂着"高校"。**
   - `date.toml` 新增 `poi_routing = "city_date"`：每个城市读自己的
     `data/cities/<key>/pois_date.csv`；没建包的城市**如实返回空候选**
     （与矩阵"宁缺毋假"同一口径），不再悄悄借用大连的数据。
   - 网页：date 模式下「高校/场景」下拉整行让位，约会面板内出现**城市**下拉
     （`/api/options` 新增 `date_cities`，显示城市名而非校名）；结果页 metaLine
     在 date 场景显示「城市 大连」而不是「高校 dalian」，数据覆盖行同步改口径。
   - `/api/date/info`、`/api/date/locate`、`/api/date/brief` 全部接受 `city` 参数。

2. **筛选细化。**
   - 场次下拉新增「自定义时间…」：数据文件里没有的那一场也能手填开场时刻钉死。
   - 面板新增「自定义固定安排」行：任意地点 + 时刻 + 时长（看落日、逛展），
     走 `anchors` 直通，与电影/订座同一硬锚点通道。

3. **一句话行程优先于面板筛选。**
   - `service/date_mode.query_overrides()` 从一句话里**只认写明了的**：
     显式 HH:MM 与中文时刻（"下午2点半"→14:30，自动补零 9:30→09:30）、
     点名的商圈、点名的地点（支持"星海渔港"匹配"星海渔港(星海广场店)"）。
   - 合并规则在 `/api/date/brief`：文本写了的维度覆盖面板勾选，
     没写的维度照旧走面板；冲突过程写进 `plan.meta["date_query_overrides"]`
     （conflicts + picked），网页如实展示"哪里被一句话改掉了"。

测试：`tests/test_date_mode.py` 扩到 30 项（新增 query_overrides 解析、
城市路由、冲突优先级、自定义锚点直通四组），全量 376 个测试全绿。
