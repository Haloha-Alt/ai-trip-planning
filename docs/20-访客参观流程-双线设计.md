# 20 · 两套行程：校内"优化" 与 访客"可执行"

> 版本 v1.0 ／ 2026-11-03 ／ 已跑通一条真实链路：需求 → 行程 → **模型生成的入校简报**。
> 核心判断：**访客要的不是"最优路线"，是"照着做不会白跑一趟"**。

---

## 一、两条线，差在目标上

| | 校内学生（`daily`） | 校外访客（`visit`） |
|---|---|---|
| 目标 | **优化**：少绕路、时间利用率高 | **可执行**：几点到哪个门、要不要预约、每站看什么、赶不上怎么办 |
| 时间窗 | 07:00–22:00，可碎片 | 09:00–17:00，**硬边界**（校史馆 16:30 停入） |
| 站数 | 4–8 | 4–6（多了走不完） |
| 权重 | 体验 45 / 省钱 25 / 时间 20 | **体验 45 / 时间 30** / 省钱 15（访客不在乎省几块） |
| 数据范围 | 全校 + 周边（含星海、万达） | **只在校区内**（校外点会把动线拉成通勤） |
| 附加产出 | 每站 reason | **入校简报**：预约、证件、交通、动线、注意事项、待确认项 |

## 二、为什么"入校须知"不能只靠模型写

模型会给你一个**不存在的预约入口**、一个**错的闭馆日**。访客按错的说明跑一趟，比没有说明更糟。

所以这里做了分层（和 `narrate`/`parser` 同一条纪律）：

```
事实层（可核查）   data/cities/dalian/visitor_guide.json  ← 每条带 source + 查阅日期
    ↓ 只许引用，不许新增
措辞层（模型）     llm/guide.py  → 一句话概括 + 时间线 + 每站看点 + 注意事项 + 待确认
    ↓ 模型挂了
兜底层（规则）     _fallback()  → 一条事实换一句话，照样能看
```

## 四、真实跑出来的样子（模型 DeepSeek-V4-Flash）

需求：*"我是外校学生，周六上午来大连理工参观，想看图书馆和校史馆，中午在食堂吃饭，下午在校园里逛逛，晚上还要赶高铁，别太赶"*

模型的输出（节选，原文见 `design/visit_sample.md`）：

> **凌水主校区半日游：从南门进，沿河走到图书馆**
>
> 出发前：提前 1–2 个工作日通过 i大工小程序或网页端提交入校申请，需填写姓名、手机号、单位/学校及**校内联系人教工号**；等审批短信；入校当日带**身份证原件**……
>
> 时间线：09:00 从南门入校 → 凌水河畔步道 → 西山生活区广场 → 伯川图书馆（外观，入馆需校园卡）→ 令希图书馆
>
> 需要注意：**"周一校史馆闭馆，且 16:30 停止入场，本行程未安排，注意避开"**
>
> 需要现场确认：入校政策、伯川图书馆是否对外开放、可打 0411-84706482

最后那句是这篇最有价值的地方：**模型没有硬编一个校史馆进去，而是承认"这次没排上，你注意别白跑"**。这正是"事实归事实、措辞归措辞"带来的效果。

## 七、接到 API 只要 5 行

```python
# api/routes.py 新增
def get_guide(req):
    body = req.get("body") or {}
    r = _run_plan(body, body.get("scenario") or "visit", body.get("strategy"), False)
    from llm.guide import briefing
    from service.usecases import llm_client
    return _ok({"guide": briefing(r, city=r.request.city or "dalian",
                                  persona=body.get("persona", "visitor"),
                                  client=llm_client(), enabled=True)})

# ROUTES 里加一行
```

## 八、修掉一个真错误：访客不能进图书馆自习

**问题**：原来的访客行程把「伯川图书馆」排成 120 分钟自习。访客进不了馆，这是**内部人员的行为**。
根因不是算法，是数据：`pois.csv` 只描述"这是什么地方"，**没有"谁能进"这一维**。

### 8.1 修法：可达性规则（数据，不是代码）

`visitor_guide.json` 增加 `access_rules`：

| category | level | 访客停留 | 说明 |
|---|---|---|---|
| 图书馆 / 自习室 | `view_only` | **10′** | 馆内需校园卡，访客看外观 |
| 体育馆 | `view_only` | 10′ | 馆内需预约/收费 |
| 宿舍 | `exclude` | — | **直接从行程去掉**，并写 warning |
| 食堂 | `need_card` | 30′ | 能否用餐到门口确认 |
| 教学楼 | `open` | 15′ | 公共区域可走，上课中的教室不进 |

`service/usecases.py` 新增 `apply_visitor_rules(resp, guide)`：按 category 套规则，
**压缩掉的分钟数顺延给后面的站**（整条轴前移），所以 arrive/leave 仍然自洽。

实测对比（同一句需求）：

```
修前  10:18-12:18  伯川图书馆  120′
修后  10:18-10:28  伯川图书馆   10′  ｜馆内需校园卡/玉兰卡，访客一般只能看楼前广场与外观
```

## 九、分步向导：提前讲清"现在该干什么"

`design/visit-wizard.html`（自包含，进度存 localStorage，可打印）：

| 能力 | 做法 |
|---|---|
| **提前告知** | 出发前 2–3 天就该提交申请 —— 这一步排在行程最前面，不是塞在备注里 |
| **追踪进度** | 8 步清单 + 顶部进度条，勾掉一步自动跳到下一步 |
| **下一步指引** | 大卡片只显示**当前这一步**：做什么、在哪、怎么去、要带什么、完成标志 |
| **落后提醒** | 用当前时间对比计划时间，晚 >10 分钟提示"后面的站可能要跳过一站" |
| **不丢状态** | `localStorage` 存进度，关掉手机再打开接着走 |

八步是：① 提交入校申请 → ② 确认审批 + 定线路 → ③ 刷身份证入校 → ④–⑦ 校内四站 → ⑧ 原路出校。
由 `design/make_wizard.py` 从「规划结果 + 入校须知」直接生成 —— **行程一变，向导自动跟着变**。

## 十、要不要再申请定位 Key？**不用**

| 想要的效果 | 现有能力 | 要不要新 Key |
|---|---|---|
| 显示"我在哪" | 浏览器 **H5 Geolocation**（`navigator.geolocation`） | **不需要** |
| 精确到"我进了哪栋楼" | 无（需蓝牙信标 / Wi-Fi 指纹 / 室内地图 SDK） | 要，但**不值得** |
| 校方平台那种室内定位 | 属校方测绘资产 | 要，且拿不到 |

两个前提要知道：
1. **H5 定位必须 HTTPS 或 localhost**。你现在用 `http://127.0.0.1:8000` 是本机，可以直接用；
   发给同学走 `https://`（Cloudflare Tunnel 那条路）也能用；走明文 http 的局域网地址，浏览器会拒。
2. 定位只用于"高亮当前站 + 判断是否落后"，**不做导航**（导航要实时路网，成本高且不稳）。

> 结论：**不用申请任何新 Key**。真要做室内定位，那是另一个项目量级。

## 十一、为什么你没看到"主题按钮"和"地图界面"

这是信息差，我说明白：

| 你看到的 | 在哪 | 状态 |
|---|---|---|
| 模型开关 + 「模型开/关对比」按钮 | **真实页面** `web/index.html`（左侧输入区，第 168–176 行附近） | ✅ 已合入 |

也就是说：**原型是设计稿，真实页面只加了模型开关**。所以你没看到主题按钮，是正常的。

### 合并进真实页面的三步（约 2 小时）

1. **抽 CSS 变量**：把 `index.html` 里写死的颜色换成 `--paper/--ink/--accent/--rule` 等
   （原型里已经有一套，直接搬），`<html data-theme>` 切换，右上角加三个 30×22 的小按钮；
2. **加地图抽屉**：右下角常驻浮标（`position:fixed`）+ 右侧 420px 抽屉，
   里面放现有的 `pane-map`（高德卫星 + 站点连线），去掉原「地图」页签；
3. **接联动**：点时间轴上的站 → 抽屉打开并高亮对应 marker（同一份 `select(poiId)`）。

风险最低的顺序就是这样：**先换色（纯 CSS）→ 再挪地图（结构）→ 最后做联动（逻辑）**。
每一小步都能单独回滚，不会一次性把页面改崩。
